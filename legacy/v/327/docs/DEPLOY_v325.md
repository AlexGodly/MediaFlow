# Deploy MediaFlow v325 — Native Workspace Public Pages

**v325 requires a new Supabase SQL migration**. This migration is not applied just by uploading the website ZIP. Back up your database and review the public data you plan to publish first.

1. **Backup:** Keep an independent database backup and copies of your existing deployed website files. The earlier v323 *in-database* backup is not an independent offsite backup, and does not include any changes since it was made.
2. **Database:** Open Supabase SQL Editor for the correct MediaFlow project. Confirm the v323 public-showcase migration is present. Run `docs/SQL_v325_workspace_public_state.sql` (included in this package). It adds the new `mf_public_workspace_v325` table and owner/read-only RLS policies. It does not replace the old tables.
3. **Frontend:** Upload the **entire v325 package contents** to the root of your GitHub Pages MediaFlow repository. This includes versioned `assets`, `index.html`, `404.html`, `sw.js`, `manifest.json`, `version.json` and application source files. Commit/deploy as usual.
4. **PWA:** Wait until GitHub Pages finishes deploying, then reload the web app or install the available PWA update. Verify the app reports version 325.
5. **Republish:** Sign in as the public profile owner and open **Public Profile → Profile Studio → Refresh published pages** or **Save and publish**. Leave the page open while all sections upload. Large Libraries may take substantial time; each uploaded chunk contains at most 150 titles/sessions/items.
6. **Verify public access:** Open the owner's public URL in a signed-out/private window and confirm Library, Collections, Personal Order, Old System, History and Statistics use original Workspace-style pages and display the **owner's** records. Verify hidden sections are inaccessible and guest mutation attempts cannot change data.
7. **Verify own isolation:** When signed in as another account, view the profile, interact with public search/filter/layout controls, then return to your own Workspace. Your private Library, status filters, settings and sessions must remain unchanged.

**Privacy:** v325 publishes detailed title and consumption records, potentially including title notes and session notes, for enabled tabs. Review this content before publication. Publication remains opt-in through Save/Refresh published pages; editing in guest tabs stays disabled.

**Important implementation limitation:** v325 calls the actual source render functions for Library, Collections, Personal Order, Old System and History. Public Statistics uses a sanitized snapshot generated by the actual `renderStats()` function. Write actions, private-only dialogs, and unaudited interactions cannot be enabled in visitor views.

**If SQL is missing:** v325 shows a data-missing warning and offers the previous published public view as a temporary fallback. Apply the migration and republish before considering the new tabs deployed.
